The snapshot has limitations that must remain visible:

- Response `required` lists and explicit nullability are largely absent. Examples establish test inputs, not exhaustive guarantees. An empty schema does not justify making every model optional.
- Mutation schemas use a `RAW_BODY` string wrapper generated by the documentation system; request examples show actual JSON object bodies. Do not send a literal `RAW_BODY` field.
- Global security declares Bearer `sec0`; the [application-authentication guide](https://developer.themoviedb.org/docs/authentication-application) also documents `api_key`, which the package uses.
- Human [tagged-images](https://developer.themoviedb.org/reference/person-tagged-images) and [keyword-movies](https://developer.themoviedb.org/reference/keyword-movies) pages mark deprecation, while the snapshot flags are false. Both facts are retained.
- Movie recommendations has an empty response schema and `{}` example. Recommendation image nullability and legacy current-user account routes/default ID 0 lack sufficient authoritative evidence for full-alignment claims. Preserve the API behavior explicitly until evidence supports migration.
